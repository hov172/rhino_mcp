# macOS Installer Package — Design Spec
**Project:** rhino-mcp  
**Date:** 2026-05-25  
**Status:** Approved (senior dev review pass 4 — 2026-05-25)

---

## Goal

Produce a signed, notarized macOS `.pkg` installer that any studio can double-click to deploy rhino-mcp across one or many machines with multiple user accounts. A single build script (`scripts/build-installer.sh`) re-generates the package on each release from one source-of-truth version in `pyproject.toml`.

---

## Architecture Overview

```
scripts/
├── build-installer.sh                         ← master build + sign + notarize script
└── installer/
    ├── preinstall                              ← system guard checks (must be chmod +x)
    ├── postinstall                             ← configures current console user (must be chmod +x)
    ├── rhino-mcp-configure.sh                  ← per-user configurator: Rhino plugin + AI clients (must be chmod +x)
    ├── com.ayala.rhino-mcp.configure.plist     ← LaunchAgent template
    └── resources/
        ├── welcome.html
        ├── license.txt
        └── background.png

Output: release/rhino-mcp-<version>-arm64-installer.pkg
```

The installer is a **notarized product archive** (`productbuild`) wrapping two component packages built with `pkgbuild`. Signed with `"Developer ID Installer: Jesus Ayala (N859JA9UCJ)"` and notarized via `xcrun notarytool`.

> **Architecture note:** The bundled `.venv` is compiled for the build machine's architecture (arm64). For Intel or mixed fleets, a separate build is required. The output filename includes `-arm64` to make this explicit. `distribution.xml` declares `hostArchitectures="arm64"` to block accidental installation on Intel Macs.

## Component Packages

### Component 1: `rhino-mcp-server.pkg`
Identifier: `com.ayala.rhino-mcp.server`

| Source (build-time) | Destination on target machine | Permissions |
|---|---|---|
| Pre-baked `.venv/` (built at final install path) | `/Users/Shared/rhino_mcp/.venv/` | `755` dirs, `644`/`755` files, `root:wheel` |
| `rhino_plugin/release/rhino-mcp.rhp` | `/Users/Shared/rhino_mcp/plugin/rhino-mcp.rhp` | `644` |
| `VERSION` file (generated by build script) | `/Users/Shared/rhino_mcp/VERSION` | `644` |
| `scripts/installer/rhino-mcp-configure.sh` | `/usr/local/bin/rhino-mcp-configure` | `755` |

> **No `src/` directory needed.** `uv pip install` places `rhmcp` into the venv's `site-packages/`. The MCP command `python -m rhmcp` resolves it from there. There is no separate source directory in `/Users/Shared/rhino_mcp/`.

Includes `preinstall` and `postinstall` scripts.

### Component 2: `rhino-mcp-launchagent.pkg`
Identifier: `com.ayala.rhino-mcp.launchagent`

| Source | Destination |
|---|---|
| `com.ayala.rhino-mcp.configure.plist` | `/Library/LaunchAgents/com.ayala.rhino-mcp.configure.plist` |

## Installation Paths & Rationale

- **`/Users/Shared/rhino_mcp/`** — world-readable (mode `1777` on macOS), survives user account changes, single copy of the Python venv for all accounts. `/Users/Shared/` is already used by Rhino on this system for the License Manager, confirming it is accessible to all users.
- **`/Users/Shared/rhino_mcp/plugin/rhino-mcp.rhp`** — staging location. Rhino does NOT auto-scan `/Library/Application Support/McNeel/` or `/Users/Shared/McNeel/Rhinoceros/8.0/` for plugins (only `Plug-ins/` inside the latter is used for License Manager). The only proven path is per-user `~/Library/Application Support/McNeel/Rhinoceros/8.0/Plug-ins/`. The configure script copies there for each user.
- **`/Users/Shared/rhino_mcp/VERSION`** — version string (e.g. `0.15.1`). Read by `rhino-mcp-configure.sh` to compare against the user's sentinel and decide whether to re-run.
- **`/Library/LaunchAgents/`** — LaunchAgents here load for every user at GUI login (Aqua session). New plists added here during an active session are picked up by launchd immediately for all active sessions, not just future logins.
- **`/usr/local/bin/rhino-mcp-configure`** — manually runnable by any user to re-run or repair their configuration. `/usr/local/bin/` is not SIP-protected and is writable by root.

## MCP Server Command (written to all AI client configs)

```json
{
  "command": "/Users/Shared/rhino_mcp/.venv/bin/python",
  "args": ["-m", "rhmcp"]
}
```

No `uv`, no PATH dependency. The venv is pre-built at the exact final install path during packaging (required because `uv pip install` writes absolute shebangs into console script wrappers).

## Per-User Configuration

### `rhino-mcp-configure.sh` — runs as the target user

Idempotent. Reads `/Users/Shared/rhino_mcp/VERSION`, compares to sentinel at `~/.rhino-mcp-configured`. Skips if version matches; re-runs and updates sentinel if version differs.

All output appended to `~/Library/Logs/rhino-mcp-configure.log` (script uses `$HOME` which is set correctly in user context; does NOT use `~` in the LaunchAgent plist itself).

**Handles two responsibilities per user:**

#### 1. Rhino Plugin Copy

```
/Users/Shared/rhino_mcp/plugin/rhino-mcp.rhp
  → ~/Library/Application Support/McNeel/Rhinoceros/8.0/Plug-ins/rhino-mcp.rhp
```

Creates destination directory with `mkdir -p` if absent. Overwrites on version upgrade. Matches the exact path used by the working `install-plugin-local.sh`.

#### 2. AI Client Configuration

| Client | Detection | Config file(s) | Format |
|---|---|---|---|
| Claude Desktop | `/Applications/Claude.app` exists | `~/Library/Application Support/Claude/claude_desktop_config.json` | JSON — merge `mcpServers.rhino` |
| Claude Code (CLI) | `~/.claude/` dir exists | `~/.claude/mcp.json` (server definition) **+** `~/.claude/settings.json` (`enabledMcpjsonServers` array) | JSON — both files updated together |
| ChatGPT Desktop | `/Applications/ChatGPT.app` exists | `~/Library/Application Support/ChatGPT/model_settings.json` *(path unverified — log a warning if parse fails and skip, do not hard-fail)* | JSON — merge `mcpServers.rhino` |
| Codex CLI | `~/.codex/` dir exists | See open item #3 — MCP support in Codex CLI is unconfirmed; skip gracefully | TOML — defer to implementation |
| Codex Desktop | `/Applications/Codex.app` exists | `~/Library/Application Support/Codex/model_settings.json` *(path unverified — log warning if parse fails and skip)* | JSON — merge `mcpServers.rhino` |

**JSON merging rules (all JSON clients):**
- Python from the bundled venv performs all JSON operations (always available, no external deps).
- Read existing file → merge `mcpServers.rhino` key → write back. Preserves all other keys.
- If file does not exist: create it with the minimal required structure.
- On JSON parse error: back up broken file as `<name>.bak`, write fresh.

**Claude Code specifics — two files, both required:**
```
~/.claude/mcp.json           → add/update mcpServers.rhino entry
                               create file with {"mcpServers": {"rhino": {...}}} if absent
~/.claude/settings.json      → append "rhino" to enabledMcpjsonServers array if not present
                               create file or add key if absent
```

**Codex CLI TOML note:** `~/.codex/config.toml` uses TOML format. Python 3.11+ `tomllib` can read it (stdlib). Writing requires `tomli_w` which is not a project dependency and should not be added to `pyproject.toml`. Defer to open item #3.

### LaunchAgent (`com.ayala.rhino-mcp.configure.plist`)

```xml
RunAtLoad       = true
LimitLoadToSessionType = Aqua        (GUI login only — not SSH)
Program         = /usr/local/bin/rhino-mcp-configure
```

> **No `StandardOutPath`/`StandardErrorPath` in the plist.** Tilde (`~`) is not expanded in LaunchAgent plist files — paths would be taken literally. The configure script handles all logging to `~/Library/Logs/rhino-mcp-configure.log` itself via shell `$HOME` expansion.

The configure script exits immediately (0) if `~/.rhino-mcp-configured` contains the current version string. No repeated work on subsequent logins.

### `postinstall` script

Detects the console user and runs the configure script immediately so the installing admin is configured without logging out:

```bash
# Ensure world-readable/executable permissions FIRST so configure can use the venv
chmod -R a+rX /Users/Shared/rhino_mcp/

CONSOLE_USER=$(stat -f "%Su" /dev/console)

# Guard: skip if no GUI user (headless) or if console is root (no user session)
if [ -z "$CONSOLE_USER" ] || [ "$CONSOLE_USER" = "root" ]; then
    echo "No GUI session detected — run rhino-mcp-configure manually to configure AI clients and install the Rhino plugin"
    exit 0
fi

sudo -u "$CONSOLE_USER" -H /usr/local/bin/rhino-mcp-configure
```

`-H` sets `$HOME` to the target user's home directory. Called from root (postinstall always runs as root), so no password is required. `chmod -R a+rX` runs first so the venv Python binary is executable before configure calls it.

## Build Script (`scripts/build-installer.sh`)

### Inputs

| Source | Value |
|---|---|
| Version | Parsed from `pyproject.toml`: `python3 -c "import tomllib; print(tomllib.load(open('pyproject.toml','rb'))['project']['version'])"` |
| Signing identity | `INSTALLER_SIGNING_ID` env var (default: `"Developer ID Installer: Jesus Ayala (N859JA9UCJ)"`) |
| Apple ID | `APPLE_ID` env var |
| App-specific password | `APPLE_APP_PASSWORD` env var |
| Team ID | `APPLE_TEAM_ID` env var |

Env vars loaded from `.env` if present (never committed to git). Build script fails with a clear message if any required env var is unset.

### Build Sequence

```
1.  Read VERSION from pyproject.toml
2.  scripts/build-plugin.sh               → dotnet build Release
3.  scripts/package-plugin.sh             → release/rhino-mcp.rhp + .yak
4.  Assert yak output filename contains $VERSION — fail immediately if mismatch
5.  chmod +x scripts/installer/preinstall
                scripts/installer/postinstall
                scripts/installer/rhino-mcp-configure.sh
6.  Create /Users/Shared/rhino_mcp/ on build machine if absent
    (world-writable by default, no sudo needed)
7.  uv venv --clear /Users/Shared/rhino_mcp/.venv
    uv pip install <repo-root> --python /Users/Shared/rhino_mcp/.venv/bin/python
    (--clear overwrites any existing venv from a prior build; venv built at exact
     final install path so absolute shebangs are correct on target)
8.  echo "$VERSION" > /Users/Shared/rhino_mcp/VERSION
9.  Copy release/rhino-mcp.rhp → /Users/Shared/rhino_mcp/plugin/rhino-mcp.rhp
10. Stage Component 1 payload into /tmp/rhino-mcp-pkg1/ (full filesystem layout,
    install-location will be /):
      mkdir -p /tmp/rhino-mcp-pkg1/Users/Shared/rhino_mcp
      cp -RL /Users/Shared/rhino_mcp/.venv  → /tmp/rhino-mcp-pkg1/Users/Shared/rhino_mcp/
      cp -RL /Users/Shared/rhino_mcp/plugin → /tmp/rhino-mcp-pkg1/Users/Shared/rhino_mcp/
      cp /Users/Shared/rhino_mcp/VERSION    → /tmp/rhino-mcp-pkg1/Users/Shared/rhino_mcp/
      mkdir -p /tmp/rhino-mcp-pkg1/usr/local/bin
      cp scripts/installer/rhino-mcp-configure.sh
                                            → /tmp/rhino-mcp-pkg1/usr/local/bin/rhino-mcp-configure
    CRITICAL — use cp -RL (not cp -R) for the venv:
      uv creates venv Python binaries as symlinks into uv's own Python cache
      (~/.local/share/uv/python/cpython-3.13-macos-aarch64-none/bin/python3.13).
      cp -R copies symlinks as-is → dangling symlink on every target machine →
      MCP command silently broken. cp -RL dereferences all symlinks and copies
      the real binary, making the pkg fully self-contained with no build-machine
      path dependencies.
    (A single pkgbuild component can only have one --install-location. Using /
     with a full filesystem tree under the staging root is the only way to place
     files in both /Users/Shared/rhino_mcp/ and /usr/local/bin/ in one component.)

    Stage Component 2 payload into /tmp/rhino-mcp-pkg2/:
      mkdir -p /tmp/rhino-mcp-pkg2
      cp scripts/installer/com.ayala.rhino-mcp.configure.plist → /tmp/rhino-mcp-pkg2/
11. pkgbuild --root /tmp/rhino-mcp-pkg1
             --install-location /
             --scripts scripts/installer
             --identifier com.ayala.rhino-mcp.server
             --version $VERSION
             /tmp/rhino-mcp-server.pkg
12. pkgbuild --root /tmp/rhino-mcp-pkg2
             --install-location /Library/LaunchAgents
             --identifier com.ayala.rhino-mcp.launchagent
             --version $VERSION
             /tmp/rhino-mcp-launchagent.pkg
13. Generate distribution.xml:
      title "Rhino MCP v$VERSION"
      hostArchitectures="arm64"
      minimumSystemVersion="13.0"
      soft check: /Applications/Rhino\ 8.app (warn, don't block)
      both component pkgs listed; customize option enabled
14. productbuild --distribution distribution.xml
                 --resources scripts/installer/resources
                 --package-path /tmp
                 rhino-mcp-$VERSION-arm64-unsigned.pkg
    (--package-path /tmp tells productbuild where to find the component .pkg files
     generated in steps 11–12)
15. productsign --sign "Developer ID Installer: Jesus Ayala (N859JA9UCJ)"
                rhino-mcp-$VERSION-arm64-unsigned.pkg
                rhino-mcp-$VERSION-arm64.pkg
16. xcrun notarytool submit rhino-mcp-$VERSION-arm64.pkg
          --apple-id "$APPLE_ID"
          --password "$APPLE_APP_PASSWORD"
          --team-id "$APPLE_TEAM_ID"
          --wait
    (prints UUID on start; --wait blocks until Apple returns result)
17. xcrun stapler staple rhino-mcp-$VERSION-arm64.pkg
18. mkdir -p release/
    cp rhino-mcp-$VERSION-arm64.pkg release/rhino-mcp-$VERSION-arm64-installer.pkg
    rm -f rhino-mcp-$VERSION-arm64-unsigned.pkg rhino-mcp-$VERSION-arm64.pkg
    rm -rf /tmp/rhino-mcp-pkg1 /tmp/rhino-mcp-pkg2
           /tmp/rhino-mcp-server.pkg /tmp/rhino-mcp-launchagent.pkg
```

> **Build machine side-effect (expected):** `/Users/Shared/rhino_mcp/` is created on the developer's machine as a valid local install. Leave it in place — it serves as a working local deployment for the developer and matches exactly what target machines receive.

## Error Handling

### `preinstall`
- macOS < 13 → exits 1, blocks install with human-readable message
- Rhino 8 not found → warning only, install proceeds (MCP server still usable)

### `postinstall`
- Plugin staging directory (`/Users/Shared/rhino_mcp/plugin/`) missing → exits 1 (critical)
- `chmod -R a+rX /Users/Shared/rhino_mcp/` runs first — venv Python must be executable before configure is called
- `stat /dev/console` returns empty or `root` → log manual instructions, exit 0; never run configure as root
- `sudo -u "$CONSOLE_USER" -H ...` fails → logged, exit 0 (LaunchAgent handles on next login)

### `rhino-mcp-configure.sh`
- Each client block wrapped in isolated error trap — one failure never skips others
- JSON parse error → backup + fresh write
- ChatGPT/Codex Desktop path unverified → log "config path unverified, skipping" if file not found at expected location
- Codex CLI → skip entirely with log message until open item #3 resolved
- All errors → `~/Library/Logs/rhino-mcp-configure.log` (creates `~/Library/Logs/` with `mkdir -p` first)

### `build-installer.sh`
- `set -euo pipefail` — fails fast on any step
- Pre-flight: asserts `dotnet`, `yak`, `uv`, `pkgbuild`, `productbuild`, `productsign`, `xcrun` exist
- Pre-flight: asserts `APPLE_ID`, `APPLE_APP_PASSWORD`, `APPLE_TEAM_ID` set
- Step 4: version assertion on yak output filename — catches plugin/server version mismatch before packaging
- Step 16: notarytool UUID printed to stdout so it can be looked up manually on timeout

## Version Matching

Single source of truth: `pyproject.toml`.

The build script propagates VERSION to:
- `pkgbuild --version` on both component packages
- `distribution.xml` title and `version` attribute
- `/Users/Shared/rhino_mcp/VERSION` file (read by configure script for sentinel comparison)
- Output filename `rhino-mcp-<version>-arm64-installer.pkg`
- Sentinel written to `~/.rhino-mcp-configured`

Step 4 asserts the yak output filename contains `$VERSION` — catches any plugin/MCP version drift before it reaches the pkg.
